## Context

AgentLab 的单个 React SPA 承载首页、试炼、工作台、结果、交付与 Replay 六个产品状态。现有 API、Monaco 编辑器和后台真实运行已经稳定；本变更只替换前端的视觉和呈现结构。用户要求直接以 Hallmark 仓库 MIT 许可下的 Tally 示例为基础，并用 Cobalt 示例改善首页的证据表达。

## Goals / Non-Goals

**Goals:**

- 锁定一套浅色靛蓝设计系统，让六个状态成为同一工程产品而非独立页面。
- 用真实的任务、状态、指标、截图和 Evidence 作为所有可视化内容。
- 在 320、375、414、768 和桌面宽度保持可用、无横向滚动、键盘可见焦点。
- 采用 Tally 的工作台信息密度、指标卡、细线边界和圆角面板；首页采用 Cobalt 的简洁证据结构。

**Non-Goals:**

- 不修改 API、数据模型、任务评分、真实 Runner、受控世界或历史 Proof。
- 不复制 Hallmark 示例的品牌、文案、客户名、价格或虚构业务指标。
- 不引入 Tailwind、组件库、图表库或新的运行时依赖。

## Decisions

- 在根目录写入 `design.md`，定义 token、字体角色、间距、交互和页面族；原因是六个 SPA 状态必须共享系统。替代方案是每页单独套主题，但会造成产品割裂。
- 将 Tally 的公开 CSS token 和布局思想适配为本地 CSS 变量，而非运行时加载外站样式；原因是可构建、可审计、不依赖第三方可用性。
- 将首页组织为“实况标签 + 明确承诺 + 真实证据面板”，将工作台组织为“任务 rail + 代码主区 + 真实运行侧栏”；原因是匹配各自的使用目标。
- 移除假浏览器 chrome；截图存在时用真实截图，不存在时用真实后台状态文本。替代方案是保留装饰圆点，但会误导用户。

## Risks / Trade-offs

- [浅色主题与 Monaco 深色编辑器反差较大] → 用明确边界和工作台壳体承接编辑器，不改编辑器的语义配色。
- [页面代码仍集中在 `App.tsx`] → 保持本次功能边界，使用语义 className 降低 CSS 耦合；不进行无关组件重构。
- [外部示例未来变化] → 使用本地复制的 token 与结构，不依赖运行时网络资源。

## Migration Plan

1. 构建后的静态资源由既有 FastAPI `StaticFiles` 自动提供。
2. 如需回滚，只需恢复前端文件和 `design.md`，后端和 session Evidence 不受影响。
